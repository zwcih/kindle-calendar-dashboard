# Kindle 设备端

根目录 `dashboard.py` 是服务端图片生成器，行为不变；本目录只保存设备运行源码，不含私人配置、图片、日志、固件、越狱组件或第三方二进制。

## 目录与依赖

将下面两个目录的**内容**分别合并到 Kindle USB 根目录的同名目录；不要把外层 `kindle` 一起复制。USB 根目录在设备上对应 `/mnt/us`：

```text
documents/
  calendar-manual-refresh.sh       手动下载并显示；首次建立缓存
  calendar-dedicated-start.sh      手动启用专用模式
  calendar-dedicated-recover.sh    退出及恢复
kindle-dashboard/
  calendar-dedicated.sh           控制器、守护与触摸监听
  calendar-auto-refresh.sh        共用单次刷新 worker
  calendar-config.sh              数据配置读取库
  config.example.conf            空白模板
  config.local.conf              自己在本地创建；禁止提交
```

需要已安装、可从书库运行 shell 入口的 libkh，以及可执行的 `/mnt/us/libkh/bin/fbink`；这些依赖不在本仓库分发。还需要设备现有的 `curl`（HTTPS、证书校验及协议限制支持）、有效 CA/系统时间、LIPC、Upstart 和脚本列出的系统命令。不会自动安装或更新任何依赖。

专用模式针对 PW3 的已核验硬件接口：`max77696-rtc.0` 相对 RTC 闹钟、`/sys/power/state` 的真实内核 suspend、含休眠计数的 `/proc/uptime`、`lab126_gui` 等服务，以及 `/dev/input/event1` 的 `cyttsp4_mt` 触屏（ARM32、16 字节 `input_event`）。启动会核对接口，不按营销型号或固件版本推断兼容性；**不保证所有 PW3 或固件都能使用**。

## 本地配置与首次使用

1. 在本地将 `kindle-dashboard/config.example.conf` 复制为同目录 `config.local.conf`，只在该文件填入真实值。Windows 编辑器使用 UTF-8 无 BOM、LF 换行。
2. `IMAGE_URL` 填可直接下载 PNG 的 HTTPS 地址；`WIFI_SSID` 填 Kindle 已保存网络的完整名称（1–32 字节，可含空格）。两个字段都必填，没有默认下载地址。Wi-Fi 密码通过 Kindle 自身设置保存，不放在此文件。
3. 将 `documents/` 和 `kindle-dashboard/` 合并复制到 USB 根目录，避免覆盖自己的其他文件。不要部署本目录说明、测试或忽略规则。
4. 安全弹出 USB，在 Kindle 上保持唤醒并连接已保存的 Wi-Fi，从书库打开“手动刷新日程”。首次成功后会创建 `/mnt/us/kindle-dashboard/dashboard.png`。
5. 已有成功缓存、网络连接正常时，打开“启用日程专用模式（半小时）”。不要在 USB 存储模式下启动。

配置是严格的 `KEY=value` **数据**，不是 shell 脚本：不要写 `export`，不要给值加外层引号，不展开环境变量或命令。仅允许 `IMAGE_URL` 与 `WIFI_SSID`，各出现一次；允许空行与以 `#` 开头的整行注释。不支持行尾注释。URL 的查询字符串按原样传递（包括 `&`、`=`、`%` 等），禁止空白、反斜杠和 authority 中的用户名/密码；需要的特殊字符应按 URL 规则编码。SSID 的空格原样保留。配置错误会输出不含真实值的错误，且在停止 GUI 或更新缓存前失败。

`config.local.conf`、运行日志、PNG 和临时文件已被本目录的忽略规则排除；空白模板不忽略。忽略规则不是保密保证，不要强制添加私人文件，不要公开运行时捕获内容。

## 专用模式行为

只通过手动入口启用；没有开机钩子、系统配置修改、自动安装或设备部署。启用后停止 GUI、防止原生屏保、关闭前光并显示缓存。每个时隙之间通过已核验 RTC 闹钟进入真实内核休眠，独立守护进程用期限租约监控运行状态并负责异常恢复。

自动刷新为 **UTC+8，06:30–22:00，每半小时一次**。启动时先显示缓存并等待下个时隙；22:00 后睡至次日 06:30。超过时隙 120 秒不补下载。电源键唤醒后，短暂等待触摸；无操作则继续等待原时隙，不把普通唤醒当作刷新请求。

单指短按后松开请求手动刷新，多次请求合并，不并发启动 worker；**单指按住至少 2 秒再松开退出**。多指操作忽略。触摸使用批量读取及 MT/BTN_TOUCH 去重；事件丢失或接触持续 30 秒触发安全恢复。专用模式内的手动刷新只跳过安静时段，仍核验直接父进程 PID/启动时间、所有权标记、active 状态及电量。

电量未知，或电量不超过 20% 且未充电，均不联网，保留缓存。单次联网预算最多 60 秒，连接就绪轮询最多 20 秒且包含在联网预算内。所有模式保留严格 HTTPS 跳转及 TLS 校验，不提供关闭证书校验的回退；校验 HTTP 状态、PNG 类型、45 字节至 5 MiB 大小和 1072×1448 的 8 位灰度 IHDR。新图片先由 FBInk 成功显示，再同文件系统原子替换缓存。下载/验证失败保留旧缓存；显示失败可能已改变屏幕，专用控制器会尝试重画旧缓存。

独立“手动刷新日程”是本次泛化改写，复用同一 worker：要求设备唤醒、专用模式完全退出，使用相同电量与下载保护，可在任何时段运行；即使图片未变化也重画，便于首次显示或回到日程页。它不会停止 GUI、禁止原生休眠或修改前光，与专用模式的单指刷新不是同一入口。

## 退出、更新与故障

长按松开退出会恢复 GUI、原前光亮度与原生休眠，并返回 Home。异常后可从书库运行“退出日程专用模式”；恢复不依赖私人配置，即使配置丢失仍可尝试恢复。不能恢复时请保留现场并诊断，不要删除活跃进程的锁或强行重复启动。已提交的 RTC 闹钟可能还唤醒一次。

更新前先退出并确认回到正常界面，再连接 USB 替换文件、编辑配置，安全弹出后重新启用。`--start` 会将控制器、worker、配置库及私人配置一起复制到 `/tmp/calendar-dedicated`，经 `nohup setsid` 隔离启动，以免 GUI 停止信号杀死书库启动器。活动会话读取该快照，USB 上的修改不会热更新；worker 始终为控制器直接子进程。恢复状态及这份私人快照留在内存临时目录，下一次正常启动按固定清单清理。

设备日志位于 `/mnt/us/kindle-dashboard/`（`dedicated-schedule.log`、`dedicated-refresh.log`、`manual-refresh.log`）。临时命令输出可能含下载地址、网络信息等隐私，排障前先脱敏。worker 中保留的无参数原生屏保及 `--dedicated-trial` 分支只是旧逻辑兼容，不是推荐的联网或生产启动路径，不要给它们添加定时/开机任务。

先前生产脚本的真实休眠、联网、界面恢复及 22:00 刷新曾在设备上成功；新手势仅安装并做过本地纯函数用例，尚未实际观察触摸效果。本次共享配置、打包和独立手动入口尚未上设备验证。**不宣称经过整夜、耐久或全面兼容性测试**。本仓库操作不包含恢复出厂设置。

## 本机开发检查

仓库现有 Python `unittest` 可运行隔离检查：

```text
python -m unittest -v test_kindle
```

需要现有 POSIX `sh`（Windows 可使用 Git 附带版本；未在 PATH 时用环境变量 `KINDLE_TEST_SH` 指定本机可执行文件）。检查只提取纯函数或模拟命令，不在开发机运行完整设备脚本，不访问 USB。
